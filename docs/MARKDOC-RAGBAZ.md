# markdoc-ragbaz document surface — v1

An additive, data-only reading surface, not MDX and not an implementation of a
production witness. Existing `renderMarkdoc`, `defineTags` and content exports
are unchanged. Models are authored read-only examples; no status is measured or
attested by rendering it.

## Build and open

```sh
npm ci
npm run markdoc-ragbaz
# Default input: reports/Fleet ledger witness architecture.md
# Default output: reports/Fleet ledger witness architecture.html

npm run markdoc-ragbaz -- --input path/to/paper.md --output path/to/paper.html
node demo/markdoc-ragbaz/worker.mjs path/to/paper.html 8788
```

The builder embeds official Markdoc, the same renderer used by previews, YAML,
paper CSS, host registry/defaults, original source, and pre-rendered content in
one HTML file. No CDN, remote font, sibling file, installation, or runtime server
is needed to open that HTML with `file:///`. Local source is selected through
FileReader (picker or explicitly enabled drop); opening a local document never silently loads demo
content. No report files are generated by the test suite.

### Content-neutral meta-document

Run `npm run markdoc-ragbaz-sci-tufte` (optionally `-- --output /srv/path/site`)
to create `markdoc-ragbaz-sci-tufte/` beneath the output site root. Unlike the
witness-paper build, this package contains a neutral opening document and only
the pinned rendering-contract snapshot. There are no assumed paper authors,
review decisions or witness-manuscript snapshots. Its companions include starter
Markdown, template source, host configuration, standalone runtime/styles, named
SVG plates, license notices and a SHA-256 file inventory. The HTML embeds what
it needs for offline opening; external companion files are useful for inspection.

Trusted host config `metaDocument: {id: markdoc-ragbaz-sci-tufte, version: 1}` opts
into `?document=<encoded URL>` and optional `&sha256=<64 hex>`. Without this flag,
existing embedded readers ignore those parameters. No parameter means no document
request. A parameter is an explicit client-side loading instruction, not server
proxy authorization. Same-origin HTTP(S) and the installed HTTPS origin allowlist
still apply; credentials, resource query strings, ambiguous paths, redirects,
wrong MIME, oversized bytes and digest mismatch remain refused. Duplicate/empty
parameters and malformed digests are refused visibly. No automatic fallback paper
replaces a failed request. Ordinary local-file Open remains available offline.

The package's template identity is separate from a loaded document's identity;
the pinned rendering contract remains tied to the template when content changes.
The render tuple's `surface` field binds host meta-document and contract-source
selection. `buildStandalone()` returns additional `assets: {runtime, styles,
credits}` alongside its existing HTML/result/payload fields for deterministic
packaging; these are outputs of the trusted build, never authored imports.

The separate `meta.ragbaz` repository owns the Worker and prefix route at
`meta.ragbaz.cc/markdoc-ragbaz-sci-tufte`. It consumes this builder from an explicit
shared checkout and records dirty/commit state. This prototype checkout is not a
released dependency; shipping a directory does not establish independent review,
account ownership, production deployment or manuscript-publication approval.

### Heartfulness presentation

`buildMetaDocument({output, template: 'heartfulness'})` (or CLI `--template heartfulness`)
builds a separate `/heartfulness/` package. The existing sci ID remains the default;
other template identifiers are refused. `metaDocument: {id: heartfulness, version: 1}`
is an installed host selection, never authored imports or a query-selected module.
Its CSS is included in the render tuple hash. The skeleton's `data-template` marks
the installed presentation; the sci surface receives neither botanical controls
nor Heartfulness CSS.

Original SVG climbing roses and section flourishes are host-owned decorative
plates, not claims about an authenticated historical source. The specimen prose
and working name are replaceable. The default uses system serif stacks and local
SVG/CSS, with no remote font/image/texture requests; the host-curated Typography
alternative described below is an explicit opt-in exception for fonts. Plain / A little /
Full bloom controls decoration; a separate switch controls deterministic paper
grain. The browser stores bounded choices in `ragbaz.heartfulness.decoration`
when available and otherwise supports session-only operation. It never writes
those preferences into manuscript content. Ornaments are hidden from assistive
technology and do not intercept pointer events. Frames are suppressed in spreads,
grain/frames in print, and all graphical decoration in forced-colors mode.

### Aether and curated typography

The installed IDs `aether-prima-materia`, `aether-sun-and-moon` and
`aether-blackening` build `/aether/prima-materia/`, `/aether/sun-and-moon/` and
`/aether/blackening/`. Their original specimen prose is separate from host SVG
plates and styles. The family header/colophon are presentation, not manuscript
authorship or proof. A plate toggle stores only `on`/`off`; variant links never
carry the current document URL. Local-file links use sibling index files.
Blackening is natively dark; explicit Light and light printing remain available.

Host config `fontAlternatives: google-curated/1` enables the installed Typography
selector and only the Google stylesheet/font origins in CSP. The normal standalone
build, without this host flag, retains `font-src 'none'`. The surface tuple binds
the host font-catalogue selection; runtime hashes bind its exact family URLs.
Documents and query parameters cannot add font services or executable styles.

System fonts are the default: no remote font request or preconnect occurs until
the reader selects Theme fonts, or a saved Theme fonts preference is restored.
The service receives a normal browser request; the UI discloses that it contacts
Google. Requests use anonymous CORS and no referrer. Google serves the CSS and font
files directly; their live bytes are not hash-pinned or embedded snapshots. This
choice can change typography/line breaks and does not attest remote font versions.
`display=swap`, local serif fallbacks, visible error status and a bounded stylesheet
timeout preserve readable content offline. Preferences store only `system`/`theme`.

Curated pairs (titles / reading text): sci Source Serif 4 / Source Serif 4, with
Source Sans 3 for tools; Heartfulness Cormorant Garamond / EB Garamond; Prima materia
IM Fell English / Crimson Pro; Sun and moon Cormorant Garamond / Spectral;
Blackening Cormorant Infant / EB Garamond. No fonts are redistributed by this build.

### Quiet reading room

Appearance is a host reader preference, not authored metadata: System follows
`prefers-color-scheme`; Light/Dark override it. Document tools expose all three.
Explicit choices use local storage key `ragbaz.sci.appearance` where permitted;
blocked storage falls back to session-only switching. The preference applies
before painting, survives document replacement and synchronizes across tabs.
Dark mode covers source views, citations, menus and trusted inline SVG plates;
print uses the light palette and white paper without changing stored appearance.

The paper has no loader, provenance strip, contract preamble or credits before it.
Only a compact hamburger bar overlays the top edge; it hides after idle or downward
scroll. Move to or tap the top edge, scroll upward, or tab to its controls to
reveal it. Focused controls and an open drawer are never auto-hidden. Reduced-motion
preferences disable the transition.

The right-hand hamburger opens a native modal drawer containing icon-labelled Open/Load and
embedded-document actions, optional drag-and-drop (off by default),
SHA-256/renderer versions and complete software notices. Escape, the close icon
or backdrop closes it; focus returns to the hamburger. Successful loading returns
focus to the paper. Closing the drawer does not discard metadata or change trust
policy. Source inspection remains an explicit in-document action. Print excludes
all reader controls. No new network requests occur just by opening the drawer.

The discreet `markdoc-ragbaz · 1` bar label opens the declared
`rendering-contract` source (or host `config.contractSource`) through the same
digest-enforcing inspector; it is not an extra section in the paper. Contents
live in a separate auto-hiding left-edge panel with a brace-and-strokes handle.
Hover reveals it; click pins it; Escape, outside interaction or navigation closes
it. Its introductory beckoning animation lasts six seconds and respects reduced motion.

### Keyboard and reading modes

The document menu exposes Flow, Paper, Fullscreen and Legend actions with keys;
the same `READING_BINDINGS` table generates menu help and the optional legend.
`f` toggles the browser Fullscreen API; Escape leaves it before dismissing nested
controls. If fullscreen is denied/unavailable the reader reports that fact and
continues normally. This is not a CSS imitation of fullscreen.

Left/right arrows enter Paper view at the current passage, then turn previous/next
spreads. Desktop (1024px+) shows two columns as facing pages; smaller screens show
one. `h` is previous and `Shift+L` next; lowercase `l` is explicitly reserved for
the legend, so this is not an unmodified Vim binding set. Up/down arrows and
`k`/`j` return to vertical Flow and scroll in the requested direction. Home/End
go to the beginning/end; PageUp/PageDown move a screen in Flow or a spread in Paper.
The menu and onscreen spread buttons provide non-keyboard access. Mode switches
retain the current containing passage (not a precise character position); reflow
may change page boundaries. Vertical wheel reading outside nested scrollable tools
returns to Flow. Print ignores pagination transforms and prints the whole document.

Unmodified reading shortcuts do not intercept typing, editable content, focused
interactive controls, source inspection or an open modal. Browser/OS modified
shortcuts are untouched; Escape can still exit fullscreen. Navigation, fullscreen
and the legend never fetch sources or change document bytes, publication state
or trust policy. The legend is off by default.

Paper mode uses A4 (210 × 297 mm) as its nominal sheet geometry, fitting two
sheet widths to desktop or one to narrow screens. Text measure is independent
of sheet size: proportional inner/outer margins keep the columns narrower than
the sheets. The binding and screen-side margins are paper-colored, not a dark or
transparent void. Screen columns use the full viewport height with no artificial
top/bottom frame padding: this is flow-first, best-effort paper simulation, not
fixed print-page breaks. Print requests A4 and restores the whole continuous
document. Superscripts attach tightly to the preceding glyph, retain a thin
separator between consecutive references, and use an expanded invisible pointer
target rather than typographic padding.

### Scientific references and manuscript frontmatter

The browser presentation replaces source tags with first-appearance superscript
numbers, deduplicated by source identity, and appends a numbered bibliography.
Meaningful authored GitHub/arXiv links retain their text and destination, with an
adjacent reference number rather than disappearing into it. Full-SHA GitHub commit
URLs are classified as commit references, not content digests. Cards abbreviate
their identifiers and link to the exact commit. Ordinary navigation remains links.
Hover/focus displays a bibliographic atom without a network request; click pins
it. Explicit Read source retains the existing digest and inert-preview policies.
At 1024px and above the default is a right-margin card; smaller screens use a
bounded tooltip card. Reading options permit `margin` or `wide` (tooltip) modes;
space constraints override margin on narrow displays. Escape and close restore
reference focus. Link decoration is absent until hover/focus.

Optional `sources[].bibliography` fields are `authors` (string array), `title`,
`year`, `venue`, `version`, `locator`, and `description`. Descriptions explain what
the destination contributes before its revision details. Missing fields are not invented:
repository ownership, path and pinned revision may be derived from a GitHub URL,
but are not asserted to be personal authorship, a publication date or authenticity.
Digest declarations and version references remain distinct from verification.

### Scientific identifier links

Plain prose identifiers in a finite, explicit set become ordinary external links:
`DOI:…` and `doi:…` to `https://doi.org/…`, `PMID:…` to PubMed,
`PMCID:PMC…` to PubMed Central, and `arXiv:…` (modern or legacy identifiers,
with optional `vN`) to arXiv. Display text is preserved; trailing sentence
punctuation and unbalanced closers stay outside the link. Matching is
case-insensitive for the prefix and skips inline code, fenced code, existing
Markdown links, SVG, adapter templates and the host-owned source-inspection
control. Generated anchors use `rel="noreferrer noopener"` and
`class="identifier-link"` with `data-identifier` set to the finite kind.

No network request is made during rendering; navigation occurs only if a reader
follows a link. These are convenience links, not verification that the work
exists, is current, is peer reviewed, is retracted, or has the claimed authors.
A document can opt out with `renderDocument(source, { identifiers: false })`;
the default is enabled.

Optional `document.entities: [{name, aliases, description, source, url, provenance}]`
defines authored first-mention introductions. Plain text matches skip headings,
code, existing links and SVG; matching respects word boundaries and adds only one
numbered introduction per entity. Introductions share the citation card and
notes/reference numbering, but are labelled editorial introductions, not retrieved
evidence. `source` may name declared documentation; `provenance: [{label, value}]`
retains classified inspection details outside the main prose. No definition is
invented from a project name, and hover does not fetch. Explain the entity's role
in the prose as well: a margin note should help, not make the argument unintelligible
when skipped.

Optional `document.figures: [{title, illustration}]` selects host-owned vector
plates by exact matching `figure` tag title. The prototype provides only
`weftmark` and `nostoi` illustrations in its trusted browser implementation; unknown
names remain ordinary text figures. Inline SVG has a fixed viewBox, an accessible
image description and print-safe conceptual diagrams. Documents cannot supply SVG,
scripts, image URLs or executable imports, and the CSP remains unchanged. Full
captions and explanatory prose remain in the Markdown. These authored conceptual
plates are not runtime observations or deployment attestations. First-mention
introductions may point to their illustrated project card. Diagrams use muted
cyan-blue paper tones and restrained orange emphasis, with monochrome boundaries
and print fallbacks; narrowly displayed diagrams may scroll without widening the page.

Optional `document.authors: [{name, role}]` and `document.authorSummary` provide
a compact expandable author line. Record actual human and model identities;
do not infer other collaborators from the harness or invent model provenance.
`document.manuscript.received` is an ISO calendar date. A publication stamp requires
`review: complete`, `published: YYYY-MM-DD`, and explicit `signals: {human: true,
assistant: true}` recorded after mutual review completion. Builds/tests never set
these fields. Until then, the stamp says Publication pending. These are authored
editorial records, not cryptographically authenticated approval evidence.
The stamp opens Manuscript & revisions in the document drawer, populated from
`document.revisions: [{date, version, description}]`. Never backdate, invent a
receipt date, or silently mark a draft published.

`worker.mjs` also exports a Worker `fetch` handler: bind `ASSETS` to the directory
of built HTML. It delegates GET/HEAD to that binding, returns 405 otherwise and
503 when unbound; it is not a network proxy or a second renderer. Local HTTP
serves exactly the already-built bytes at `/` and `/index.html`, on loopback.

## Authoring contract

The official AST's frontmatter attribute is parsed as either a JSON mapping or
YAML 1.2 core data. Custom tags, alias expansion, duplicate keys, unsafe object
keys, executable fields and unsupported schema versions are refused. The
authoritative merge is **shallow** host defaults, then document metadata. There
are no implicit variables, imports, partials, includes, or executable expressions.
Ordinary report metadata such as top-level `title`, `date`, and `author` is
preserved; `document.title` takes precedence for the window title. No frontmatter
is required for ordinary Markdown; omitted schema defaults to v1.

```yaml
---
schema: ragbaz.document/1
document:
  title: An architecture proposal
  status: proposal
dialects: [paper@1, plan@1, models@1]
assets:
  - id: publication-logo
    role: logo
    url: ./logo.svg
    alt: Publication name
  - id: repository
    role: repository
    url: https://github.com/example/repository
  - id: appearance
    role: theme
    ref: paper@1
settings:
  theme: paper@1
sources:
  - id: background
    title: Background paper
    url: https://github.com/owner/repo/blob/aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa/background%20paper.md
    # Optional expected SHA-256 of original bytes, 64 hex characters:
    # sha256: ...  # compatible alias; must agree with integrity.digest
models:
  - id: topology
    title: Proposed topology
    data:
      ledger: append-only proposal
      observation: none
views:
  - id: topology-table
    model: topology
    kind: table
---
# An architecture proposal

{% callout kind="warning" title="Evidence boundary" %}
This is a proposal, not an observation.
{% /callout %}

{% example title="Illustration" %}
Normal **Markdown**, tables and fenced code work inside blocks.
{% /example %}

{% aside title="Background" %}
Inspect the source without leaving the document.
{% /aside %}

{% source ref="background" /%}

{% model ref="topology" /%}

{% view ref="topology-table" /%}
```

Collections `assets`, `sources`, `models`, and `views` are arrays of mappings
with unique IDs matching `[\w.-]{1,100}` (reserved prototype keys excluded).
Additional model data is inert. Views support `table` (field/value fallback) and
`json`; unsupported kinds visibly refuse rather than fabricate a diagram.

| Family | Tags | Allowed attributes |
| --- | --- | --- |
| `paper@1` | `callout` | `kind`, `title` |
| | `aside`, `figure` | `title` |
| | `source` (self-closing) | `ref` |
| `plan@1` | `example` | `title` |
| | `milestone`, `decision` | `title`, `status` |
| `models@1` | `model`, `view` (self-closing) | `ref` |

Callout kinds: `warning`, `note`, `info`, `proposal`, `observed`, `verified`.
Statuses: `proposal`, `observed`, `verified`; these remain explicitly labelled
**authored claims**. Unknown/incompatible tags preserve escaped source in visible
refusal blocks. Missing closing tags and unexpected attributes are diagnosed.
Fenced tag examples are inert, even though Markdoc 0.5 normally parses their
children. Markdoc's legacy setext-heading behavior is not rewritten into another
Markdown dialect: use ATX `#` headings.

## Reusable APIs

Import `@ragbaz/common/content/markdoc-ragbaz` or the direct source file:

```js
import { renderDocument, BUILTIN_REGISTRY } from './src/content/markdoc-ragbaz.js';
const result = await renderDocument(source, {
  defaults: { schema: 'ragbaz.document/1' },
  registry: BUILTIN_REGISTRY,
  policy: { origins: ['https://trusted.example'] },
  fetcher: fetch,
});
// result: html, manifest, headings [{id,level,text}], diagnostics [string],
// clean, usedDialects, theme (safe declarations), tree, resolvedRegistry.
```

- `parseDocument(source, defaults?)` → `{ast, manifest, tags, source}`.
- `themeCSS(tokens)` → validated semantic CSS declarations or throws.
- `safeLink(value)` → HTTPS/mailto/fragment link or null. Relative links are
  inert and diagnosed, avoiding unintended `file:///` navigation.
- `githubRawURL(blobURL)` → immutable raw URL; requires HTTPS GitHub blob with
  a full 40-hex revision. Keeps escaped paths (e.g. `%20`); strips display
  fragments. Refuses branch names, credentials, queries, traversal and ambiguous
  escaped separators/dots/double escapes.
- `resourceURL(input, policy, {pinned?, digest?})` → host-authorized URL or throws.
- `fetchResource(input, {policy, digest?, integrity?, purpose?, verifiedCache?, pinned?, fetcher?, media?, maxBytes?})`
  → `{text, sha256, expectedSHA256, state, url, integrity}`. `digest` is the
  transport-level alias of manifest `sha256`. SHA-256 is over raw bytes before UTF-8
  decoding. A matched digest is integrity, **not publisher authentication**.
- `sha256(bytes)`, `escapeHTML(value)`, `CONTRACT`, `LIMITS` are also exported.

Core imports no product policy, filesystem, DOM or Worker binding. It reuses
`TOKENIZER_DEFAULTS` and the existing content layer's raw-HTML-escaping policy,
but does **not** reuse legacy `defineTags`' unrestricted attribute forwarding.
The safe final tree serializer permits named HTML elements and named attributes
only. Original HTML is text, images are inert placeholders, expressions are
refused, author HTML/class annotations are refused, and source previews never
use arbitrary HTML/iframes.

## Host configuration and lazy registries

### Fragment compatibility boundary

`ragbaz.surface/1` and `ragbaz.render/1` are **local renderer contracts**, not
fleet-wide artifact authorities or alternatives intended to supersede Fragment.
The concurrent Fragment 0.1 draft at
`0d9114a6014721bfba52e4d2b54d33dc373b7ee5`
(`packages/fragment/docs/PROTOCOL.md` on `origin/codex/fragment-artifact-protocol`)
defines its own artifact envelope, strict fields and versioned `extensions`.
The paper proposes **Fragment transport + Markdoc content**; this implementation
does not import, validate, emit or integrate that envelope. Interoperation needs
an explicit mapping/versioned extension covering content/dialect identity,
assets, theme tokens, provenance, capability degradation and render identity,
with validation and compatibility tests. No automatic mapping, fleet standard,
or Fragment integration is claimed here.

`--config path/to/registry.json` selects a host-owned `ragbaz.surface/1` tuple.
The installed tuple is `skeleton: "paper/1"` plus
`implementation: "markdoc-ragbaz/1"`; unsupported skeleton/bundle identities are
rejected, not treated as aliases for the installed implementation. Host assets
and defaults are data. To install another layout, review the trusted skeleton,
CSS and builder source: documents cannot provide an implementation path.

`demo/markdoc-ragbaz/registry.json` supplies explicit origin policy and defaults.
`dialects` and `themes` extend the bundled registry. Inline dialect example:

```json
{"version":"1","tags":{"principle":{"element":"aside","attrs":["title"]}}}
```

Register that descriptor under `dialects.didactic` and declare
`dialects: [didactic@1]` in the document. Only families whose advertised tags
occur in the AST are resolved. For remote declarative JSON, the **host** entry
must have `version`, advertised `tags`, fixed `url`, and expected `sha256`.
Remote theme entries likewise require a fixed URL and digest. There is no
document-supplied JS URL, `eval`, dynamic import, CSS text or callback path.
Templates can use only `aside`, `section`, `figure`, `div`, `span`, `blockquote`
and semantic `title`, `kind`, `status`, `ref` attributes. They do not forward
arbitrary HTML attributes. Built-in semantic names retain their core meaning.
Dependencies are versioned registry refs; cycles, depth and resource budgets
are checked. Dependencies do not implicitly add tags to another family.

Theme descriptor: `{"version":"1","tokens":{"paper":"#faf8f0","ink":"#24251f"}}`.
Supported six-digit hex colors: `paper`, `ink`, `muted`, `accent`, `rule`,
`warning`. Numeric `measure` is 45–85 ch, `text-size` is 16–24 px. No arbitrary
CSS, URLs, selectors, font downloads, `@import`, declarations or expressions.
Only bundled `paper@1` exists by default; no external inspiration is claimed to
be an installed named theme. Accessibility, layout, warning labels and print
rules remain host-owned. A `theme` asset's registry `ref` takes precedence over
`settings.theme`; a document cannot give that asset a fetch URL.

All fetched required declarative resources are embedded as resolved data by
the builder, so the original document stays offline-capable. Logo/image assets
currently show explicit unavailable/alt-text placeholders instead of fetching;
repository assets are safe navigational provenance links. Relative resources
do not silently resolve to the demo or access the filesystem.

## Sources, transport and offline snapshots

Normal builds make **no network requests**. To embed source snapshots, either:

```sh
# Externally supplied mapping: {"background":"./sources/background.md"}
npm run markdoc-ragbaz -- --input paper.md --output paper.html --snapshots mapping.json

# Explicit authorization to fetch declared immutable/digest-pinned sources:
npm run markdoc-ragbaz -- --input paper.md --output paper.html --fetch-sources
```

Mapping paths are relative to the mapping file, not author-controlled paths in
the document; externally generated absolute paths such as
`{"background":"/tmp/opencode/snapshots/background.md"}` are also accepted.
Supplied source digests are checked. Each source is at most 1 MB;
at most 24 are cached, at most 4 MB total. Failed fetches or digest mismatches
fail the build by default, never fall back to latest. Explicit `warn-preview`
may embed mismatched bytes **only for inert text inspection**; the browser
rechecks snapshot and manifest digests before display. Embedded snapshots retain URLs,
digests and provenance labels. The mapping is a build input, not a mutable
browser cache. The builder exports `buildStandalone(options)` for trusted tools.

The URL toolbar intentionally loads a user-entered URL. External requests must
be HTTPS and match exact host-configured origins (the example registry allows
only `https://raw.githubusercontent.com`); same-origin HTTP/HTTPS is permitted
for a hosted reader. Optional `policy.prefixes` restricts absolute URL prefixes.
Policies are never read from document metadata. Literal/private/local target
hosts are refused unless they are the explicitly configured same origin. Host
operators must not allow internal DNS names or unsafe DNS-rebinding domains.
Requests omit credentials/referrers, reject redirects and unexpected final
URLs, require plain/Markdown media types (JSON for registry entries), enforce
streaming byte caps and an 8-second maximum timeout. CORS errors are visible;
there is no proxy escape hatch. Injected fetchers must honor AbortSignal.

Sources are loaded only when explicitly inspected and then explicitly requested,
or from an embedded snapshot. Remote source preview requires a full SHA GitHub
revision or an expected SHA-256 digest. The foreground and matched preview use the same
renderer/defaults/registry/security policy. Previews do not include recursively
or auto-fetch images/sources. Generation checks prevent stale asynchronous
loads from replacing a newer document or source. The raw source is always inert.

The payload records raw-source and runtime SHA-256 plus a `ragbaz.render/1`
tuple: source digest, skeleton digest/ID, implementation digest/ID and Markdoc
version, CSS digest, effective assets/settings/defaults, resolved registry and
snapshot digests. `renderSHA256` hashes this tuple using recursively key-sorted
JSON (array order preserved; no own digest field). This is a reproducibility
identity, not a signature or an authentication claim. Host transport policy is
not a claim about document content authenticity.

## Integrity, revisions and declarative relations (additive v1)

Every source or linked asset may carry:

```yaml
integrity:
  algorithm: sha256
  digest: aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa
  onMismatch: refuse # or warn-preview | use-verified-cache
```

The 64-hex `sha256` alias remains supported; contradictory aliases, algorithms
and policies refuse. Missing `onMismatch` means `refuse`. Hashes describe bytes,
not authorship. Missing digests retain the prior immutable-GitHub pinning rule.
Assets that are only links/placeholders do not have their bytes fetched or
verified merely because they declare a digest; declarations are not evidence.
Executable runtime is always host-installed, never document-selected. Themes
and dialects remain strict host-registry resources; relaxed policy refuses even
when bytes match. No author JS, CSS or executable callback path is introduced.

`integrityDescriptor(entry)` normalizes to `{algorithm, digest, onMismatch}`.
`verifyResourceBytes(Uint8Array, entry, {purpose?, verifiedCache?})` returns
`{text, sha256, expectedSHA256, state, integrity}`. Default purpose `trusted`
always refuses mismatches. Only the host's explicit `purpose: 'inert-inspector'`
can apply a relaxed policy:

- `warn-preview`: returns `state: 'unverified'`, which the browser puts through
  `textContent` **only**, visibly labelled UNVERIFIED with both digests. It is
  not rendered as Markdoc, never enters a trusted source/main surface and cannot
  resolve a dialect/theme. Main source and pinned identity remain unchanged.
- `use-verified-cache`: requires host `verifiedCache.get(expectedDigest)` returning
  `Uint8Array`; rehashes the returned bytes and uses them only if they match.
  Missing/tampered cache refuses, never substitutes latest or mismatched bytes.
  Returns `state: 'verified-cache'`, `receivedSHA256` and expected digest.
  This is available only to source inspection, not runtime/dialect/theme loading.
- Other states: `matched` (expected digest matched), `unpinned` (digest recorded,
  no expected digest supplied). UTF-8 is fatal-decoded and a BOM is preserved so
  embedded snapshot text can be re-encoded and checked byte-for-byte.

The browser's cache adapter is limited to embedded snapshots, rehashed on use;
it does not write a persistent/network cache. The builder has no verified-cache
adapter, so that policy refuses a build-time mismatch. Network errors never
silently trigger any cache policy; the policy concerns digest mismatches only.

Optional source `revision` uses the provider-derived immutable identity exactly:

```yaml
revision:
  provider: github
  pinned:
    owner: owner
    repo: repo
    commit: aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa
    path: background paper.md # decoded path, not URL-escaped
  tracking:
    mode: branch # branch | tag; both require a named ref
    ref: main
relations:
  - kind: supersededBy # supersedes | supersededBy | related
    url: https://arxiv.org/abs/2401.12345v3
    evidence:
      provenance: Author-supplied notice; requires independent review
      url: https://example.org/notice # optional evidence link, never auto-fetched
```

For GitHub, `tracking: {mode: release, semver: true}` selects GitHub's latest
published non-draft/non-prerelease release and its explicit `tag_name`; optional
`semver: true` refuses non-semver-looking tags, it does not infer versions from
dates or names. Without tracking, a click discovers `default_branch` from the
repository API. Branch/tag/release checks query `/repos/{owner}/{repo}/commits`
with **`path`, `sha` and `per_page=1`**, not a repo-wide latest commit. Path and
ref are separately URL-encoded; named branches use `refs/heads/` and tags/releases
use `refs/tags/`, preventing a same-name tag from shadowing a branch. GitHub blob and raw URLs must contain full
40-hex revisions; all 13 pinned GitHub Markdown sources in the paper can be
derived without additional metadata. This statement describes URL support, not
a live check of their repositories or current upstream state.

For arXiv, the equivalent descriptor is:
`{provider: 'arxiv', pinned: {id: '2401.12345', version: 1}, tracking: {mode: 'latest'}}`.
Discovery accepts canonical `https://arxiv.org/abs/...` and `/pdf/...[.pdf]`,
modern and legacy identifiers, optional `vN`; unversioned identities use
`version: null` and cannot establish `current`. Checks use
`https://export.arxiv.org/api/query?id_list=<base-id>&max_results=1`, not PDF
content. `parseArxivAtom(xml)` returns `{id, version, url}` from one Atom entry.
It is a bounded, fail-closed structural XML subset parser shared by Node/browser:
balanced elements, namespace scopes, quoted attributes, predefined/numeric
entities and comments. DTDs/custom entities, CDATA, unsupported processing
instructions, malformed/unbalanced structure, wrong namespaces, multiple entries,
unversioned results and identity mismatches refuse. It does not claim general
XML standards conformance; valid unsupported syntax may refuse rather than be
recovered. No DOM dependency, dependency change, external entity resolution,
payload substring extraction, or XML-driven network request is used.

`discoverSourceProvider(url)` is pure and returns `{provider, pinned}` or null.
`checkSourceRevision(source, {fetcher?, now?, timeout?})` is called only by the
inspector's **Check source updates (network)** button. It returns:
`{status, observedAt, timestampAuthority, original, tracking?, latest?, relationship?, effectiveURL?,
evidence: [{url, sha256, role}], evidenceRole, reason}`. Status is `current`
(equal GitHub revision or equal arXiv vN), `latest`
(positively compared descendant GitHub path commit or higher arXiv vN),
`unknown` (unsupported/unversioned/noncomparable/empty path history), or `error`.
The observation time is a **client clock, not a trusted timestamp**. GitHub's
path commit can predate a later pinned repository commit containing the same
file: **inequality alone never establishes newer history**. When the candidate
differs, a second bounded request uses
`/repos/{owner}/{repo}/compare/{pinned}...{candidate}?per_page=1`.
The response's `base_commit.sha` must match the pin, its API `url` must bind the
same repository and both full SHAs (GitHub's `permalink_url` can abbreviate them), and `merge_base_commit.sha`,
`status`, nonnegative safe-integer `ahead_by` and `behind_by` must agree:

- `ahead`, positive ahead/zero behind, merge base equal to pin → `latest`,
  `relationship.kind: descendant`.
- `behind`, zero ahead/positive behind, merge base equal to candidate → `unknown`,
  `relationship.kind: ancestor`. The tracked ref may lack file changes present
  in the pin; ancestry alone does not establish byte equality or current status.
- `diverged`, both counts positive, merge base different from both endpoints →
  `unknown`, `relationship.kind: diverged`; no ordering or supersession inferred.
- Equal path candidate and pin → `current`, `relationship.kind: equal`, no
  comparison request needed. An empty path list → `unknown`,
  `relationship.kind: no-path-commit`, never current.
- Wrong identities, malformed shape or contradictory status/count/merge-base
  evidence → `error`, not a successful observation.

For compared results, `relationship` also carries `base`, `candidate`, `mergeBase`,
`providerStatus`, `aheadBy` and `behindBy`; equality carries `base`/`candidate`.
The hashed path-query and comparison responses retain distinct evidence roles;
`effectiveURL` is the comparison endpoint when used. A positive descendant
establishes newer path history, **not necessarily changed bytes** (e.g. reverts),
document quality, publisher authenticity or supersession. Tag tracking is comparison to
that named tag, not discovery of every tag. Release tracking does not enumerate
or sort all releases. No API ordering is inferred from authored dates.

Endpoints are fixed in reviewed host code to `api.github.com` and
`export.arxiv.org`; the builder adds these exact origins to CSP. Documents cannot
change endpoints or authentication. No redirects are allowed; credentials and
referrers are omitted, JSON/Atom media and response shape are checked, each
response is capped at 256 KB and at most 8 seconds. API HTTP/rate, CORS, offline,
timeout and refusal errors remain visible without a proxy or fallback. Provider
availability/CORS was **not live-tested by this implementation**. arXiv Atom IDs
using `http://arxiv.org/abs/...vN` are normalized to HTTPS for identity matching;
this does not cause an HTTP request. The public arXiv API may omit browser CORS
headers: Node or an authorized provider host can read a permitted response, but
a direct `file://` browser check may return a clearly labelled `error`/unknown
availability rather than a version observation. No proxy is added and no browser
availability is promised. Unsupported domains get no provider
and show unknown. Opening a document or source inspector never starts an update
check; stale async observations cannot overwrite another selection.

Original source, latest observation and authored relations are displayed
separately. Relations require a kind, safe URL and nonempty evidence provenance;
their assertions/evidence links are not fetched or promoted to verified facts.
No revision or supersession is automatically rewritten. No signing service,
publisher authentication, trusted timestamp or production readiness is claimed.

## Evidence and limitations

### Distributed software notices

Each generated HTML includes escaped, inert, expandable credits containing full
installed Markdoc MIT and YAML ISC LICENSE texts, not just SPDX identifiers or
esbuild legal comments. Markdoc's source-map inventory also requires notices for
its vendored markdown-it, entities (BSD-2-Clause), uc.micro, mdurl (including
Joyent/Node attribution), linkify-it and punycode, plus PEG.js generated-parser
attribution. These texts were inspected from the actual npm package LICENSE
files; Markdoc's patched markdown-it is not asserted to be an unmodified release.
The builder checks esbuild inputs, pinned package versions, vendored inventory,
generated-parser identity and notice availability, refusing unreviewed changes.
Notices participate in render identity and require no build-time network fetch.

ragbaz-common is licensed GPL-3.0-or-later (`LICENSE`, since 2026-11-18). The
builder embeds the full license text in every standalone page's credits, beside
the dependency notices. The license covers ragbaz-common's code, not the
authored documents a page displays; those keep their own owners' terms. esbuild
is build-only; its implementation is not distributed in the browser runtime.

`npm test` includes official-AST, unsafe HTML/URL/attribute/frontmatter/theme,
unknown/incompatible schema, immutable resolution, fetch refusal and offline
bundle tests. If Chromium exists, a **headless** cold `file:///` smoke runs with
network disabled, exercises snapshot preview, relative-resource refusal and an
actual FileReader selection. No visible window or production deployment occurs.

Prior verification on 2026-10-15: clean `npm ci` succeeded with zero audit vulnerabilities;
`npm test` passed **77/77**, zero skipped (including full-notice and missing-license
refusal coverage). Headless Chromium passed 15 offline
checks including stale previews and simulated CORS refusal. Real loopback HTTP
and the Worker asset-binding adapter returned identical HTML; an npm-command
temporary fixture build completed with zero diagnostics. Actual remote network
fetches and the coordinator-owned paper build were not exercised by this work.

After the additive integrity/provider implementation on 2026-10-15, `npm test`
passed **89/89**, zero failed/skipped. Chromium passed **22** offline checks,

This is a bounded document surface, not an audited hostile-content sandbox,
